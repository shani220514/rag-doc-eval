1. **定位**：检索评测只评 Retriever Top5。生成是后一步：短答用规则打分，不用 LLM 当裁判。  
2. **题集**：40 题，五种意图（穿透 / 源文档 / 模块陷阱 / 字段约束 / 路径忠实）。  
3. **门禁**：Recall@5 ≥ 80%、模块准确率 ≥ 90%、路径幻觉率 ≤ 5%；有效题为 0 必挂。  
4. **可复现**：pytest 72 条离线通过；CI 不读 `.env`、不开网络。  
5. **边界**：标题切片和 dry-run 清单已有；live upsert 未实现。示例语料是虚构采购订单 API，不是公司内部系统。

## 1. 项目是什么

`rag-doc-eval` 是一套**离线优先的文档检索评测工具**。

它只回答这个问题：

> 给定一道题，检索返回的 Top5 切片里，有没有出现预期原文？

它**不是**知识库问答产品，也**不**调用大模型生成答案，也**不**用 LLM 当裁判。

示例语料是仓库内自写的**虚构采购订单 API**（知识卡 + 接口说明），与任何公司内部系统、商业文档平台无隶属关系。把 `cards/`、`sources/`、`eval/goldens.yaml` 换成自己的文档和题目后，打分器、门禁、密钥检查和 CI 可以继续用。

---

## 2. 明确不做的事

| 不做 | 说明 |
|------|------|
| 生成式问答混进检索分 | 短答单独打分，不改变 Recall@5 / 模块准确率 / 路径幻觉率 |
| LLM-as-judge | 命中判定是子串规则，不是模型打分 |
| 线上文档入库 | `--dry-run` 只列出标题切片和 sha256。不带 `--dry-run` 时退出码 2，v1 未接真实上传 |
| 真实业务数据 | 仓库内没有客户数据、内部接口、账号密钥 |

## 3. 目录说明

```
cards/                      分层知识卡（允许同步的语料）
sources/api/                接口说明（允许同步的语料）
eval/goldens.yaml           40 题黄金集（评测输入）
eval/path_whitelist.yaml    每次评测从语料重生成，不要当手改真理
eval/last_report.md         最近一次评测报告
eval/last_retrieve.json     最近一次切片缓存
scripts/eval_retrieve.py    检索评测 CLI（fixture / live）
scripts/eval_generate.py    生成评测 CLI（--answers 或 --model / --temperature）
scripts/eval_scoring.py     检索规则打分与门禁
scripts/chunk_md.py         按标题把 Markdown 切成段
scripts/sync_guard.py       路径白名单 + 密钥形态拦截
scripts/kb_sync.py          --dry-run 列出每段 chunk_id 与 sha256；live upsert 为 v1 桩
scripts/path_extract.py     从 Markdown 抽出 /v1/... 路径
tests/fixtures/chunk_pick.yaml  正式夹具每题选用哪一段
tests/                      离线 pytest
.github/workflows/eval.yml  离线测试 + dry-run + fixture 评测
```

只有 `cards/**/*.md` 和 `sources/**/*.md` 允许进入「可上传」范围。`.env`、评测报告、密钥形态正文会被拦截。

## 4. 切片与入库检查

语料先按标题切开，再决定能不能入库。评测夹具里的切片和这里列出的段是同一批：一节一段，整份文件不会粘成一条。

| 规则 | 行为 |
|------|------|
| 怎么切 | 每个 ATX 标题（`#` 到 `######`）单独成段，正文直到下一个标题 |
| 文首 YAML | 没有标题，挂在第一节。采购卡的别名因此留在「导读」 |
| 没有标题的文件 | 整篇作为一段，标题用文件名（不含扩展名） |
| `chunk_id` | `相对路径#标题`，例如 `cards/purchase-order.md#列表接口`。同文件标题重复时，第二条起写成 `标题-2` |
| sha256 | 这一段正文的 UTF-8 摘要。只改某一节时，其它节的摘要不变 |

`kb_sync.py --dry-run` 先用 `sync_guard` 检查整份文件，再打印每一段。路径必须在 `cards/` 或 `sources/` 下；正文出现 `Bearer `、`password`、`AKIA` 会退出码 2，一段都不会列出。

```text
cards/purchase-order.md#列表接口 <sha256>
sources/api/list-orders.md#List purchase orders <sha256>
```

当前采购卡列出 7 段：导读、列表接口、详情接口、状态接口、确认接口、已知坑、相关链接。四份接口说明各 1 段，一共 11 段。

正式夹具 `tests/fixtures/fake_retrieve.json` 按 `tests/fixtures/chunk_pick.yaml` 为每题放入对应的那一段（最多 5 段）。问分页时，Top5 里是「列表接口」，确认接口的路径不会一起出现。

真正上传仍未实现。不带 `--dry-run` 时，缺密钥或密钥已齐都退出码 2，不发请求。索引快照要等上传接通之后才有。

## 5. 评测怎么走

```
黄金集题目
    → 取 Top5 切片（fixture JSON，或可选的线上 Retrieve）
    → 规则打分（must_hit / must_not_hit / Top1 模块 / 抽出路径）
    → 汇总指标
    → 与绝对阈值、可选 baseline 比较
    → 写 last_report.md、last_retrieve.json
```

两种取切片方式：

1. **Fixture（默认可演示）**  
   从 `tests/fixtures/fake_retrieve.json` 读每题的切片。每题是标题切出来的一段（见 `chunk_pick.yaml`），不是整篇粘在一起。不读 `.env`，不开网络。
2. **Live（可选）**  
   需要 `RETRIEVE_API_KEY`、`RETRIEVE_WORKSPACE_ID`、`RETRIEVE_INDEX_ID`。HTTP JSON 形态与 DashScope Retrieve（`output.nodes`）兼容。缺任一变量时退出码 **2**，不发请求。

如何读报告：`eval/last_report.md` 里 `index_id` 为空，表示这是 fixture 证据，不是线上索引跑出来的结果。

生成接在检索后面，单独写 `last_generate_report.md`，不改上面的检索门禁。

```
同一批 Top5
    → 短答（--answers 文件，或 --model / --temperature 调用模型）
    → 规则打分（must_hit 都在短答里；短答中的 /v1/ 路径必须出现在这题 Top5）
    → 答案命中率 ≥ 80%，答案路径幻觉率 ≤ 5%
```

`--answers` 和 `--model` 同时出现时用文件里的短答，不发请求。只有模型、没有 `GENERATE_API_KEY` 时退出码 2。夹具短答在 `tests/fixtures/fake_answers.json`，改某一题的字符串就会改变该题的生成分。

## 6. 黄金集

文件：`eval/goldens.yaml`  
题量：**40**（A=16，B=8，C=8，D=4，E=4）

| 意图 | 含义 | 主要判定 |
|------|------|----------|
| `A_penetrate` | 命中知识卡某一层说法 | Top5 拼接文本包含 `must_hit` |
| `B_source` | 命中 `sources/api` 中的约束 | 同上 |
| `C_module_trap` | 发运/销售类问题不应把采购订单操作文档排到 Top1 | Top1 文件名落在禁止列表则记 `module_mixup` |
| `D_constraint` | 字段或时间窗口约束 | `must_hit` 子串 |
| `E_path_faithful` | 问到的 `/v1/...` 路径应被抽出且在白名单内 | 路径抽取 + 白名单 |

命中规则：`must_hit` 每一项都必须作为**大小写敏感的原文子串**出现在 Top5 拼接文本中。题目改了、卡片改了，只要针消失，离线测试会先失败，而不是静默把题打成 miss。

## 7. 指标和门禁

每题先给出主分类，再汇总。

主分类优先级（高 → 低）：

1. `retrieve_error`：取切片失败或 fixture 缺该题
2. `retrieve_miss`：`must_hit` 未全部出现，或命中了 `must_not_hit`
3. `module_mixup`：仅 C 类，Top1 落在禁止文件名
4. `path_hallucination`：抽出的路径不在白名单，或落在该题 `forbidden_paths`
5. `ok`

汇总指标：

| 指标 | 计算 |
|------|------|
| Recall@5 | 未出现 `retrieve_miss` 的题数 / 带 `must_hit` 的有效题数 |
| 模块准确率 | C 类有效题中未出现 `module_mixup` 的比例 |
| 路径幻觉率 | 非法路径条数 / 抽出路径条数 |

有效题 = 主分类不是 `retrieve_error` 的题。

门禁：

- 有效题为 0（全失败或空题集）：**不通过**（不会按空分母显示 100% 通过）
- Recall@5 ≥ 80%
- 模块准确率 ≥ 90%
- 路径幻觉率 ≤ 5%
- 若存在 `eval/baseline_report.md`：Recall@5 相对 baseline 下降不得超过 5 个百分点；模块准确率不得低于 baseline；路径幻觉率不得高于 baseline

baseline **不会**由脚本自动改写，需要人工审阅后再复制冻结。

CLI 退出码：

| 码 | 含义 |
|----|------|
| 0 | 评测跑完且门禁通过 |
| 1 | 评测跑完但门禁未过 |
| 2 | live 模式缺环境变量，或同步 live 未实现 / 被拦截；不联网 |

## 8. 怎么跑

依赖：Python 3.10+（CI 使用 3.11），见 `requirements.txt`（`pytest`、`pyyaml`）。

```bash
python -m pip install -r requirements.txt

# 离线测试（不需要密钥、不访问网络）
python -m pytest tests/ -v

# 同步 dry-run：按标题列出切片的 chunk_id 和 sha256，不上传
python scripts/kb_sync.py --dry-run

# fixture 评测（采购订单 40 题）
python scripts/eval_retrieve.py --fixture tests/fixtures/fake_retrieve.json

# DF 订单样例：未挂门禁（退出码 0）
python scripts/eval_retrieve.py --goldens eval/samples/df-order/goldens.yaml --fixture eval/samples/df-order/fake_retrieve.json

# DF 订单样例：故意挂门禁（退出码 1，报告写到 gate-fail/）
python scripts/eval_retrieve.py --goldens eval/samples/df-order/goldens.yaml --fixture eval/samples/df-order/fake_retrieve_fail.json --out-dir eval/samples/df-order/gate-fail

# 生成评测：--answers 优先，即使带了 --model / --temperature 也不调用模型
python scripts/eval_generate.py --fixture tests/fixtures/fake_retrieve.json --answers tests/fixtures/fake_answers.json
```

可选线上检索：复制 `env.example` 为 `.env`，填入 `RETRIEVE_*` 后执行：

```bash
python scripts/eval_retrieve.py
```

pytest 不会在 import 时读取 `.env`。fixture 模式不读 `.env`。可用 `EVAL_NO_DOTENV=1` 强制跳过。`EVAL_OUT_DIR` 可把报告写到临时目录，避免覆盖仓库里已提交的 `eval/last_report.md`。

### 常见追问

**为什么生成不并进检索分？**  
检索错了，生成再漂亮也是错的。Retriever 单独门禁。生成看另一份报告：短答要带上 `must_hit`，抽出的路径必须已经在这题 Top5 里。`--answers` 用来换短答；`--model` 和 `--temperature` 只在没给答案文件时生效。

**为什么不用 RAGAS / LLM-as-judge？**  
规则子串命中零成本、可复现、CI 能卡。LLM 裁判有波动、有费用，也不适合当唯一门禁。本仓库不排斥以后加生成评测，只是 v1 故意不做。

**fixture 报告里 100% 算成绩吗？**  
不算。夹具是为了验证打分器、报告和 CI 通路。`index_id` 为空就是这个意思。夹具现在按标题段放置，用来确认打分器能对上「该节是否被选中」。接到真实 Retrieve 后，同一套门禁才会变成线上成绩。

**切片和 Top5 是一回事吗？**  
入库切片是按标题从 Markdown 切出来的段，`kb_sync.py --dry-run` 把它们列出来。评测时的 Top5 是这些段里被选回来的最多 5 段。dry-run 不上传，所以还没有索引快照。

**C 类模块陷阱在测什么？**  
RAG 常见失败不是「完全没召回」，而是召回了相邻模块（发运/销售 vs 采购）。C 类要求 Top1 不能落在禁止文件名上。

**空跑为什么必须失败？**  
如果有效题为 0，Recall 的分母是空的。很多实现会默认 100%。这里把这种情况写成硬失败，避免「什么都没检索到却显示全绿」。

**密钥是怎么防的？**  
`sync_guard` 只允许 `cards/`、`sources/` 下的 Markdown；正文出现 `Bearer `、`password`、`AKIA` 直接拒绝。pytest 与 fixture 评测不读 `.env`。
